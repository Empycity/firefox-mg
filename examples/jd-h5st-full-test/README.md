# JD h5st local protocol runner

This runner signs and requests `pc_home_feed` without Playwright/Camoufox in the business path.

## What is dynamic

- `fp`: generated by `js_security_v3_0.1.4.js` and cached in local state.
- `tk06/localTk`: generated locally by the JD SDK and sent to `https://cactus.jd.com/request_algo`.
- `tk03/algo`: returned by `request_algo`, cached in local state, refreshed by the SDK when needed.
- `expandParams`: collected and encoded by the SDK inside the Node VM.
- `jsToken/eid`: generated by running `analysis/pc-tk.js` in a Node VM and calling `https://jra.jd.com/jsTk.do`.
- visit cookies, `shshshfpa/shshshfpx/shshshfpb`, `sdtoken`: generated or refreshed locally and persisted under `state/`.

No browser-captured token or cookie is required at runtime.

## Requirements

```bash
python3 -c "import curl_cffi"
```

`curl_cffi` is used only for the final HTTPS transport because Node `fetch` returns 403 with the same valid signature/cookies, while Chrome TLS and `curl_cffi` Chrome impersonation return 200.

## Run

Index page one-click request:

```bash
python3 examples/jd-h5st-full-test/index.py
```

Edit `PAGE` at the top of `index.py` to change pages. The Python entrypoint clears
`state/index_state.json` before and after each run by default, so `fp`, `tk03`,
`jsToken/eid`, protocol cookies, and `sdtoken` are regenerated instead of reused.

Search page one-click request:

```bash
python3 examples/jd-h5st-full-test/search.py
```

Edit `KEYWORD`, `PAGE`, and optional `S` at the top of `search.py`. Search requires
logged-in cookies in `config/search_cookie.json`; this file is ignored by git and
was exported from the current logged-in browser request. The search signer uses
SDK appId `f06cc` and query appid `search-pc-java`.

Generate signed params:

```bash
npm --prefix examples/jd-h5st-full-test run sign -- --page=1
```

Send the business request:

```bash
JD_FETCH=1 node examples/jd-h5st-full-test/index.js --page=1
```

Force h5st remote initialization refresh:

```bash
JD_FORCE_H5ST_INIT=1 node examples/jd-h5st-full-test/index.js --page=1
```

Print generated request headers for debugging:

```bash
JD_PRINT_HEADERS=1 node examples/jd-h5st-full-test/index.js --page=1
```

Use an external login cookie for a one-off validation request:

```bash
JD_COOKIE_FILE=/tmp/jd_login_cookie.json JD_FETCH=1 node examples/jd-h5st-full-test/index.js --page=1
```

`JD_COOKIE_FILE` is optional. Without it, the script generates and refreshes its own anonymous protocol state.

## Files

- `signer.js`: Node VM runner for `js_security_v3_0.1.4.js`, including local `request_algo` initialization.
- `risk.js`: Node VM runner for `pc-tk.js`, generating `jsToken/eid`.
- `index.js`: local signer for `www-jd-com` index page requests.
- `index.py`: PyCharm-friendly one-click index page request runner. Configure `PAGE` in code and run it directly.
- `search.js`: local signer for `search-pc-java` search requests.
- `search.py`: PyCharm-friendly one-click logged-in search request runner.
- `fetch_curl_cffi.py`: pure protocol Chrome TLS transport.
- `state/index_state.json`: index page dynamic state cache.
- `state/search_state.json`: search page dynamic state cache.
