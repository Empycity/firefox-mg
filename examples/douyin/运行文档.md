# 运行文档

## 1. 运行前检查

1. 使用 `pythonProject` Conda 环境：

   ```bash
   /opt/miniconda3/envs/pythonProject/bin/python -m pip install -r requirements.txt
   ```

2. 确认系统存在 Node.js 和 `ffmpeg`。
3. 确认同目录存在：

   ```text
   creator_publish.py
   creator-runtime-contract.json
   security-runtime.json
   security-storage-full.json
   bdms-runner.js
   assets/bdms_1.0.1.16.js
   cookie.txt
   ```

4. 确认 `cookie.txt`、`security-runtime.json`、`security-storage-full.json`、
   `creator-runtime-contract.json` 来自同一浏览器会话。
5. 敏感文件权限建议为 `0600`。

## 2. 当前默认发布参数

```text
visibility_type = 1   仅自己可见
download        = 1   允许下载
timing          = 0   立即发布（本轮浏览器成功样本值）
media_type      = 4   视频
```

参数最小集合：

```text
--video 或 --video-batch   本地视频路径
--cookie-file              Cookie 文件路径
--text                     可选文案
```

`userid`、`a_bogus`、上传凭证、`Vid`、`StoreUri`、封面和 `creation_id` 均由程序
自动维护。

## 3. 连续发布 5 次

命令行：

```bash
./连续发布5次视频.sh
```

或手工命令：

```bash
PYTHONUNBUFFERED=1 /opt/miniconda3/envs/pythonProject/bin/python creator_publish.py \
  --video-batch test-videos/test-video-1.mp4 test-videos/test-video-2.mp4 test-videos/test-video-3.mp4 test-videos/test-video-4.mp4 test-videos/test-video-5.mp4 \
  --cookie-file cookie.txt \
  --text "连续发布稳定性演示" \
  --visibility-type 1 \
  --download 1 \
  --timing 0 \
  --impersonate chrome136 \
  --retries 2
```

macOS 双击：`连续发布5次视频.command`。Windows 双击：
`run-5-videos-windows.bat`。

验收标准：5 个任务全部返回 `HTTP 200 + status_code=0 + item_id`。

## 4. 安全运行态行为

本轮已实测并修正为以下规则：

| 字段 | 当前行为 |
|---|---|
| query `msToken` | 从当前 Cookie 读取；响应头 `x-ms-token` 只观测，不写回。 |
| `a_bogus` | 每个创作者接口重新生成。 |
| `bd-ticket-guard-client-data` | 复用浏览器成功请求导出的固定值。 |
| `x-secsdk-csrf-token` | 复用同一运行态固定值。 |
| `x-tt-session-dtrait` | 复用同一运行态固定值。 |
| 三枚 `__security_mc_*` | 每个发布任务开始轮换一次；任务内部保持不变。 |
| VOD/ImageX 凭证 | 每次上传由 `upload/auth/v5` 和 Apply 接口动态返回。 |

## 5. 故障排查速查

| 日志阶段/现象 | 优先检查 | 说明 |
|---|---|---|
| 启动提示缺少 `msToken` | `cookie.txt` | Cookie 必须包含 `msToken=...`。 |
| `upload-auth` 403 | Cookie、`msToken`、登录状态 | 通常表示浏览器会话相关材料需要重建。 |
| `video-apply` 失败 | 临时凭证、系统时间、网络 | `user_id` 从凭证策略自动解析，不手填。 |
| `video-upload`/CRC32 失败 | 视频完整性、网络 | 对比本地和服务端 CRC32。 |
| `video-commit` 无 Vid | `SessionKey` 配对 | Apply 返回的 `SessionKey` 只用于同一次 Commit。 |
| `video-status` 超时 | 服务端转码状态 | Vid 已产生，可延长轮询后查状态。 |
| 封面阶段失败 | ffmpeg、ImageX 响应 | 检查首帧生成和封面 `SessionKey/StoreUri`。 |
| `create-v2` 403 | 当前浏览器安全运行态 | 停止批次，重新导出成功请求和 Storage 后重建。 |
| 作品可见性不符合预期 | `visibility_type` | `0` 公开，`1` 仅自己可见。 |
| Windows CMD 乱码或命令残缺 | BAT 格式 | 使用 `run-5-videos-windows.bat`，ASCII + CRLF。 |

`create_v2` 不自动重试，避免发布结果不明确时重复创建作品。接口或算法升级后，
按 `变更排查手册.md` 分层采集浏览器成功样本并与本地请求做结构化对比。
