# 视频上传发布链路：参数与来源

本文说明整条链路每一步需要携带什么，以及参数从哪里取得。人工提供的只有
视频文件和同一浏览器会话导出的运行态/Cookie；其余字段由代码、文件内容或上
一步接口响应生成。

## 一、人工输入

| 输入 | 放置位置 | 要求 |
|---|---|---|
| Cookie | `cookie.txt` | 浏览器请求头中的完整 Cookie 值，一行保存，不带 `Cookie:` 前缀，必须包含 `msToken`。 |
| Security Runtime | `security-runtime.json` | 由当前浏览器成功 `create_v2` 和 Storage 重建，包含 CSRF、dtrait、公钥和固定 client data。 |
| 完整 Storage | `security-storage-full.json` | 同一浏览器会话的 localStorage/sessionStorage，用于审计和重建。 |
| 视频 | `test-videos/` 或命令行路径 | MP4 等 ffmpeg/VOD 支持的视频。 |
| 文案 | `--text` | 可选，默认空字符串。 |
| 发布设置 | 命令行参数 | 默认仅自己可见、允许下载、立即发布。 |

Cookie 示例：

```text
name1=value1; name2=value2; msToken=TOKEN_VALUE; name3=value3
```

不要带 `Cookie:` 前缀，不要对整行再 URL 解码。

## 二、全链路公共参数

| 参数 | 携带位置 | 来源 |
|---|---|---|
| Cookie | HTTP Cookie header | 从 `cookie.txt` 导入同一个 `curl_cffi` Session；标准 `Set-Cookie` 自动合并，退出时原子写回。 |
| `msToken` | 创作者接口 query | 从当前 Session 的 `.bytedance.com` Cookie 读取；响应头 `x-ms-token` 只观测，不覆盖 Cookie。 |
| `a_bogus` | 创作者接口 query | `bdms-runner.js` 使用 `creator-runtime-contract.json`、当前 URL、body 和 Cookie 生成；每个创作者接口重新生成。 |
| 浏览器环境参数 | 创作者接口 query | 从本地运行时契约读取，例如 `aid`、屏幕尺寸、语言、平台、时区、H.265 支持等。 |
| TLS/HTTP 指纹 | 网络层 | `curl_cffi` 的浏览器 impersonate 配置，当前使用 `chrome136`。 |
| `bd-ticket-guard-client-data` | `create_v2` header | 优先逐字节复用浏览器成功请求导出的固定值。 |
| CSRF / dtrait / REE public key | `create_v2` headers | 来自同一浏览器会话的 `security-runtime.json`。 |
| 三枚 `__security_mc_*` | Cookie | 每个发布任务开始轮换一次，任务内部保持不变。 |

## 三、接口顺序与参数来源

### 1. 获取临时上传凭证

```text
GET /web/api/media/upload/auth/v5/
```

携带：当前 Session Cookie、当前 `msToken`、新生成的 `a_bogus`、本地契约中的浏览器
query 参数。

响应产生：

| 响应字段 | 后续用途 |
|---|---|
| `AccessKeyID` | ImageX/VOD AWS V4 请求签名。 |
| `SecretAccessKey` | ImageX/VOD AWS V4 请求签名。 |
| `SessionToken` | 临时上传授权，并从内部策略解析账号绑定 `user_id`。 |
| `user_id` | 代码从 `SessionToken` 的策略 `Condition.UserId` 自动提取。 |

本轮对比结论：该响应没有发现需要写入后续 `create_v2` 的额外安全态；同一任务内
它和最终 `create_v2` 使用同一组三枚 `__security_mc_*` marker。

### 2. 申请视频上传槽位

```text
GET https://vod.bytedanceapi.com/?Action=ApplyUploadInner
```

主要 query：

| 参数 | 值/来源 |
|---|---|
| `Action` | 固定 `ApplyUploadInner`。 |
| `Version` | 固定 `2020-11-19`。 |
| `SpaceName` | 固定 `aweme`。 |
| `FileType` | 固定 `video`。 |
| `IsInner` | 固定 `1`。 |
| `FileSize` | 本地读取视频字节数。 |
| `app_id` | 固定 `2906`。 |
| `user_id` | 第一步临时凭证策略自动解析。 |
| `s` | 每次生成 11 位小写字母数字随机串。 |

请求头中的 AWS V4 `Authorization`、安全 Token、日期和 payload hash 均由临时凭证
动态签名。

响应产生：`Vid`、`StoreUri`、`UploadID`、`Auth`、`UploadHost`、`SessionKey`。
这些字段只绑定当前上传任务，不更新浏览器 Cookie 安全态。

### 3. 上传视频二进制

```text
POST https://{UploadHost}/upload/v1/{StoreUri}
```

携带：

| 参数/头 | 来源 |
|---|---|
| URL Host | Apply 响应的 `UploadHost`。 |
| URL Path | Apply 响应的 `StoreUri`。 |
| `Authorization` | Apply 响应的 `Auth`。 |
| `X-Storage-U` | 临时凭证中解析的 `user_id`。 |
| `Content-CRC32` | 本地对视频原始字节计算。 |
| `Content-Type` | 固定 `application/octet-stream`。 |
| Body | 视频原始字节。 |

大于 5 MiB 时自动执行 `init -> transfer -> finish`。这些参数由文件内容和 Apply
响应决定。

### 4. 提交视频上传

```text
POST https://vod.bytedanceapi.com/?Action=CommitUploadInner
```

请求体：

```json
{
  "SessionKey": "ApplyUploadInner 返回值",
  "Functions": [
    {"name": "GetMeta"},
    {"name": "Snapshot", "input": {"SnapshotTime": 0}}
  ]
}
```

响应的 `Vid`、宽高、时长、格式和编码用于后续处理及最终发布。它不产生后续
`create_v2` 要写入的 Cookie 或 Ticket Guard 状态。

### 5. 等待视频处理完成

```text
GET /web/api/media/video/enable/?video_id={Vid}
GET /web/api/media/video/transend/?video_id={Vid}
```

`video_id` 来自 VOD Apply/Commit。两个请求都携带当前 Cookie、`msToken` 和新生成
的 `a_bogus`。程序轮询到 `status_code=0` 且出现 `play_url` 后继续。

### 6. 生成并上传封面

程序使用 ffmpeg 提取视频第 0 秒画面，然后执行：

1. `upload/auth/v5` 获取新的临时凭证；
2. `ApplyImageUpload` 获取封面 `StoreUri/Auth/Host/SessionKey`；
3. POST JPEG 原始字节，CRC32 本地计算；
4. `CommitImageUpload`，body 为上一步的 `SessionKey`；
5. `/aweme/v1/creator/get/url/?uri={StoreUri}` 校验封面。

封面 `poster` 使用最终确认的 `StoreUri`。

### 7. 最终发布

```text
POST /web/api/media/aweme/create_v2/
```

query：当前 `msToken`、新生成的 `a_bogus`、`read_aid=2906`、本地契约中的浏览器
环境参数。

关键 headers：

| Header | 来源 |
|---|---|
| Cookie | 当前自动维护的 Session。 |
| `bd-ticket-guard-client-data` | 浏览器成功请求导出的固定值。 |
| `bd-ticket-guard-ree-public-key` | `security-runtime.json`。 |
| `bd-ticket-guard-*` 版本头 | 固定协议版本字段。 |
| `x-secsdk-csrf-token` | `security-runtime.json`。 |
| `x-tt-session-dtrait` | `security-runtime.json`。 |
| `Origin/Referer/sec-ch-ua*` | `security-runtime.json`。 |

关键 body：

| 字段 | 来源 |
|---|---|
| `text` | `--text`。 |
| `visibility_type` | `0` 公开，`1` 仅自己可见；默认 `1`。 |
| `download` | `1` 允许下载，`0` 禁止；默认 `1`。 |
| `timing` | `0` 立即发布；本轮浏览器成功样本值。 |
| `media_type` | 视频固定 `4`。 |
| `video_id` | VOD 返回的 `Vid`。 |
| `creation_id` | 每个发布任务动态生成。 |
| `cover.poster` | 自动上传封面的 `StoreUri`。 |
| `cover.poster_delay` | 当前固定 `0`。 |

完整 body 字段表见 `POST请求体参数说明.md`。

## 四、接收方不需要手填的字段

```text
user_id、AccessKeyID、SecretAccessKey、SessionToken、Vid、StoreUri、UploadID、
UploadHost、Auth、SessionKey、CRC32、视频宽高/时长/编码、封面 URI、
creation_id、a_bogus、Ticket Guard headers
```

换号或状态失效时，用 `更新运行态.py` 从同一浏览器会话的一条成功 `create_v2`
和完整 Storage 重建整套运行态。
