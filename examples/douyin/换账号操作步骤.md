# 换账号操作步骤（人工手动取信息版）

目标：换账号时手工从浏览器取齐本地发布需要的账号运行态。最终操作以
Chrome DevTools 人工导出为准，不依赖 js-reverse。

## 一、你最终只需要人工取两份文件

两份文件必须来自**同一个浏览器窗口、同一个账号、同一次成功发布之后立刻导出**：

```text
1. create-v2.curl                 成功 create_v2 请求的 Copy as cURL
2. browser-storage-current.json   同页面完整 Storage
```

然后运行 `更新运行态.py`，它会自动更新：

```text
cookie.txt
security-runtime.json
security-storage-full.json
creator-runtime-contract.json
```

重点：不要只换 `cookie.txt`。Cookie、Storage、Ticket Guard client data、CSRF、
dtrait、公钥必须是一整套。

## 二、人工操作总流程

```text
登录新账号
  -> 打开上传页
  -> DevTools Network 勾 Preserve log
  -> 手动发布 1 条小测试视频，建议仅自己可见
  -> 找到成功的 create_v2
  -> Copy as cURL 保存到 create-v2.curl
  -> Console 执行导出 Storage 脚本
  -> 保存到 browser-storage-current.json
  -> 运行 更新运行态.py
  -> 跑五视频验证
```

## 三、详细步骤

### 1. 登录新账号并打开上传页

Chrome 里登录目标账号，打开：

```text
https://creator.douyin.com/creator-micro/content/upload
```

### 2. 打开 Network 并保留请求

打开 DevTools：

```text
F12 / 右键检查 -> Network
```

勾选：

```text
Preserve log
```

过滤框可以输入：

```text
create_v2
```

### 3. 手动发一条测试视频

在页面里手动上传一个小视频。推荐设置：

```text
仅自己可见
允许下载
立即发布
```

等页面发布完成。Network 里会出现：

```text
/web/api/media/aweme/create_v2/
```

确认这条请求成功：

```text
HTTP 200
响应 JSON 里 status_code = 0
响应 JSON 里有 item_id
```

### 4. 保存 create_v2 cURL

在 Network 里点中成功的 `create_v2` 请求，右键：

```text
Copy -> Copy as cURL
```

回到本目录，保存为：

```text
create-v2.curl
```

保存方式示例：

```bash
mkdir -p log
pbpaste > create-v2.curl
```

或者手工新建 `create-v2.curl`，把剪贴板内容粘进去。

### 5. 导出完整 Storage

还是同一个浏览器页面，打开 DevTools Console，粘贴执行本目录
`导出完整Storage.js` 里的完整内容。

执行后 Console 会显示“完整 Storage 已复制”。回到本目录保存：

```bash
pbpaste > browser-storage-current.json
```

也可以手工新建 `browser-storage-current.json`，粘贴剪贴板内容。

### 6. 运行重建命令

在 `examples/douyin` 目录执行：

```bash
/opt/miniconda3/envs/pythonProject/bin/python 更新运行态.py \
  --curl create-v2.curl \
  --storage browser-storage-current.json \
  --dir .
```

成功时应输出：

```text
updated cookie.txt, security-runtime.json, security-storage-full.json, creator-runtime-contract.json
required fields ok: Cookie, URL msToken, bd-ticket-guard-client-data, csrf, dtrait, ecdh private key, ticket, ts_sign, public key
```

### 7. 验证

先做 dry-run：

```bash
/opt/miniconda3/envs/pythonProject/bin/python creator_publish.py --dry-run
```

再跑五视频：

```bash
./连续发布5次视频.sh
```

五视频日志会自动写到：

```text
log/run-5videos-YYYYMMDD-HHMMSS.log
```

## 四、create_v2 cURL 里不能缺的东西

`create-v2.curl` 必须来自**成功的最终发布接口**：

```text
/web/api/media/aweme/create_v2/
```

里面不能缺：

| 必需项 | 在 cURL 里的表现 | 用途 |
|---|---|---|
| 完整 URL | cURL 后面的 `https://creator.douyin.com/...create_v2/?...` | 提取 query `msToken` 和浏览器环境 query。 |
| `msToken` | URL query 里有 `msToken=...` | 后续创作者接口 query 使用。 |
| Cookie | `-H 'cookie: ...'` 或 `-b '...'` | 生成 `cookie.txt`。 |
| `bd-ticket-guard-client-data` | `-H 'bd-ticket-guard-client-data: ...'` | 当前稳定链路固定复用。 |
| `bd-ticket-guard-ree-public-key` | `-H 'bd-ticket-guard-ree-public-key: ...'` | 写入/校验公钥。 |
| CSRF | `-H 'x-secsdk-csrf-token: ...'` | 最终发布必带。 |
| dtrait | `-H 'x-tt-session-dtrait: ...'` | 最终发布必带。 |
| Client Hints | `sec-ch-ua*` | 建议保留，脚本会写入运行态。 |

最关键的不可缺字段：

```text
Cookie
URL 里的 msToken
bd-ticket-guard-client-data
bd-ticket-guard-ree-public-key
x-secsdk-csrf-token
x-tt-session-dtrait
```

缺其中任意一个，就重新从成功 `create_v2` 复制 cURL。

## 五、Storage 里不能缺的东西

`browser-storage-current.json` 必须包含 localStorage 里的两个 key：

```text
security-sdk/s_sdk_crypt_sdk
security-sdk/s_sdk_sign_data_key/web_protect
```

脚本会从里面读取并校验：

| 字段 | 来源 |
|---|---|
| `ec_privateKey` | `security-sdk/s_sdk_crypt_sdk` |
| `ticket` | `security-sdk/s_sdk_sign_data_key/web_protect` |
| `ts_sign` | `security-sdk/s_sdk_sign_data_key/web_protect` |
| `client_cert` | `security-sdk/s_sdk_sign_data_key/web_protect` |

一致性要求：

```text
Storage 里的 client_cert == create_v2 头里的 bd-ticket-guard-ree-public-key
Storage 里的 ts_sign == bd-ticket-guard-client-data 解出来的 ts_sign
```

`更新运行态.py` 会自动检查，不一致会直接报错。

## 六、重建后你应该看到什么

`security-runtime.json` 里应有：

```text
schema
ecdh_key
ticket
ts_sign
ree_public_key
csrf
x_tt_session_dtrait
bd_ticket_guard_client_data_header
```

发布日志里应看到类似：

```text
client_data_len=... client_data_sha256=...
dtrait_len=... dtrait_sha256=...
csrf_sha256=...
x-ms-token observed ... (held fixed, not applied)
```

不同账号的长度/hash 可以不同。关键是：同一批次里 client data、CSRF、dtrait 固定，
三枚 `__security_mc_*` 每个发布任务换一次。

## 七、常见错误

| 报错/现象 | 原因 | 处理 |
|---|---|---|
| `missing required fields: bd-ticket-guard-client-data` | 复制的不是最终 `create_v2`，或 cURL 没复制完整 | 重新 Copy as cURL。 |
| `missing required fields: x-tt-session-dtrait` | 请求头缺 dtrait | 重新复制成功 `create_v2`。 |
| `inconsistent input: URL msToken differs from Cookie msToken` | URL 和 Cookie 不是同一条请求 | 用同一条成功 `create_v2` 重新复制。 |
| `Ticket Guard ts_sign differs from Storage` | cURL 和 Storage 不是同一浏览器安全会话 | 同一个页面重新复制 cURL 并立即导出 Storage。 |
| `public key differs from Storage` | 请求头公钥和 Storage 不匹配 | 同一个页面重新取两份材料。 |
| 本地 `create_v2 403` | 运行态缺字段/过期/混用了不同会话 | 新账号重新手动发一条成功测试视频，再按本流程取。 |
